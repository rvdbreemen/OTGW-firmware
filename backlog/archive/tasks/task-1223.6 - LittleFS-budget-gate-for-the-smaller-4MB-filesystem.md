## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The FS partition shrinks (~1.125 MiB). Add a build-time check that fails when the LittleFS content (shipped assets + reserved runtime headroom for settings/logs) exceeds the partition budget, so asset growth cannot silently break the layout.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 build fails with a clear message when assets exceed the budget (demonstrated with an oversize dummy file) and passes on the real asset set
- [x] #2 Runtime headroom figure is documented and justified from TASK-1222 measurements
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-14 from TASK-1222: the 640K factory / ~1.125 MiB LittleFS figures in this task are INVALID. Measured LittleFS minimums: plain assets 1460 KiB (does not fit beside any updater), browser-only gzip 604 KiB. The candidate under gzip is factory 960K / ota_0 2240K / LittleFS 768K. Re-specify after the maintainer picks the asset lever (gzip vs dropping a UI).

2026-10-14: TASK-1224 (minified LittleFS image from a staging copy of data/, no gzip) is the asset lever that makes the 768K LittleFS budget reachable without gzip; the maintainer rejected gzip on 2026-10-14.

2026-10-14 measured with the shipped TASK-1224 pipeline (rjsmin/rcssmin, not esbuild): LittleFS minimum 1080 KiB with both UIs; 668 KiB with the classic UI dropped (the earlier 644 KiB figure was esbuild full minify). 768K budget leaves ~100 KiB runtime room with the classic UI dropped.

2026-10-15: build.py FS_RUNTIME_RESERVE_KIB = 96, itemised in the comment above it:
- 14 persistent runtime files at 4 KiB blocks (settings.ini takes 2), 60 KiB.
- 2 .tmp copies, 8 KiB.
- PIC hex download growth over the shipped copy, 33 KiB.
That totals 101 KiB; the gate allows 96 because the .tmp copies never all exist at once.
enforce_littlefs_budget() runs per target before the FS build. If mklittlefs is not installed yet (first pio build), it runs right after buildfs with required=True, so the check is never silently skipped.

Evidence: tests/test_build_staging.py TestLittleFsBudget (14 tests OK).
- An oversize dummy (random, partition-sized) exits 1 with 'LittleFS budget exceeded: assets need 1548 KiB + 96 KiB runtime reserve = 1644 KiB, partition is 1536 KiB (108 KiB over)'.
- The real minified assets pass: 1080 + 96 <= 1536.
test_build 9 OK, evaluate --quick 100%.

Note for the safeboot layout: v2-only 668 + 96 = 764 KiB <= 768 KiB, a margin of only 4 KiB. TASK-1223.13 (FSexplorer without components.css) should add margin.
<!-- SECTION:NOTES:END -->
