## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Sergeant D entry 348 (Q-347a B, 2026-11-14, 'as a fail safe guard (e.g. sat is in PWM -> reboot -> starts again in suppression)'): a heating start in continuous mode runs the PWM start sequence too. Follow-up of TASK-1924 Part 2 (beta.250, entries 338/344/347). Deliberate deviation from thermo-nova: there the start sequence is PWM-only (heating_control.py:224-225, :380-448) and continuous mode with the flame off sends the request (:476-482). Open in the entry: the return-less case of entry 45 also in continuous (read as yes).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 In continuous mode with heating requested and the flame off, CS = return + fFlameOffOffset (18.0), clamped to cold setpoint..max (satPwmFlameOffHold, as PWM); a boiler without a return temperature uses the flow, as PWM (entry 45, read as yes)
- [x] #2 After a CH flame-on the flame-off CS is held for fModSupDelay (20 s); then CS = max(request, flow - fModSupOffset) until 60 s after flame-on; then the entry-112 clamp (entries 344, 347)
- [x] #3 Gates as the PWM ON start: no override during hot water, with the request at or below the cold threshold, or with overshoot protection off (heating_control.py:384-389)
- [x] #4 Host test on the real satContinuousSetpoint/satPwmFlameOffHold: flame off then flame on, red on beta.250 (flame off -> request), green on the fix
- [ ] #5 Bench via 09: a continuous start shows return + 18 before ignition, the 20 s hold, then the follow and the clamp; no regression on PWM starts
- [x] #6 ADR-235 (or the TASK-1924 docs) names the start sequence in continuous mode
- [ ] #7 Entry 385 (387/389/391/394): every heating start (heater OFF->ON, SAT enable without a flame, boot) enters PWM first once the flow is known, with the first phase ON; no PWM->continuous switch until 60 s after the first CH flame-on of that start; host test red on origin and green on the fix; bench on the PIC unit shows the PWM-first start on the wire

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Entry 385 (PWM first), reasons entry 387; release scope entry 386. Changes entry 12 ('PWM comes back through the overshoot auto-switch', cited above satPwmDisableOnHeaterOff) and the 'auto = start in continuous' of the control_mode command (SATcontrol.ino :4451); extends entry 348.
thermo-nova (7beaaf5, local copy verified by UPSTREAM_COMMIT): PWM.__init__ -> reset() sets _enabled False (pwm.py :63, :89), restore() re-enables only a saved enabled state (:112-114); heater OFF disables PWM (heating_control.py :229-231); PWM is enabled only on a sustained overshoot (:262-305): thermo-nova starts continuous. Firmware today mirrors that: satPwmDisableOnHeaterOff leaves PWM (:1937-1938), SAT enable starts continuous (:7866), the auto command starts continuous (:4451), boot restores only a saved PWM flag (satRestoreControlMode :3962-3968).
Timing (open point of entry 385), decided by d3 under Robert's 09:30 rule with the advisor as check: A = the start sequence ends 60 s after flame-on (the start-up follow window of entries 344/347). Reason: entry 387 (2) asks for 'a small warm up'; option B (end of the first PWM ON phase) lasts at least 180 s (pwm.py :53 _on_time_lower_threshold) and up to 3600/cycles_per_hour. Recorded in docs/sat/open-questions.md; 92 asks Sergeant D non-blocking.
Code: (1) PWM entry on the heater OFF->ON edge of the control tick and on SAT enable when no flame is burning (_sat_flameOffSeen semantics: SAT coming on mid-burn behaves as before), through satSetControlMode() so the MsgID 3 veto (entries 213-215) stays the last check; never PWM while the heater is OFF. (2) Boot: reuse the deferred restore: _sat_pwmRestore = 1 on every boot, so PWM is entered on the first valid MsgID 3 reply (satPwmPermitted needs bSlaveCfgValid, SATcycles.ino :1313-1316); its 'mode moved on its own' cancel must not fire while it waits. (3) Gate: no PWM -> continuous exit (max-setpoint exit :8141 heating_control.py :203-204 copy, underheat/ADR-236, saturation, cycle-end UNDERHEAT_PWM) before the start sequence ends; the entry 214 low-load veto (safety) keeps working. (4) A PWM -> continuous switch mid-burn is no new CH start: the entry 348 flood/hold must not run again. (5) Manual 'continuous' (iRequestedControlMode 1) is only reported today (:5017, no auto-switch reads it), so PWM first applies to it too; recorded as our reading in open-questions for Sergeant D.
Tests (red on HEAD, green on the fix): OFF->ON in auto -> PWM; veto -> continuous + 348 start; boot with MsgID 3 unknown -> PWM after the first valid reply; no exit before 60 s after flame-on (cold start with request at max); exits work after; PWM->continuous mid-burn runs no second 348 sequence; SAT enabled mid-burn unchanged. Then the full test_sat_* suite (tests that pinned the continuous start go red: update each, name the entry), lowload and loop_integration alone, evaluate. Bench by 09: regression only (no SAT on hardware). ADR: /adr-kit:context first; an Accepted ADR stating the continuous start gets a superseding ADR.
