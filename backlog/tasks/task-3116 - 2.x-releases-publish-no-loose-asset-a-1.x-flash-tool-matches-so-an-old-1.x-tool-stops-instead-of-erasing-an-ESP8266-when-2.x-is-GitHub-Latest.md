## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Source: otgw-architect's draft OTGW-field-data/_comms/task_draft_latest_protect_1x_tools.md (2026-11-27); decision: Robert, question 26 'A' (DM 1575746666244472957, relayed by the coordinator). 2.x becomes GitHub Latest at the 2.0.0 stable. Copies of the 1.x flash tools read Latest and write any matching .ino.bin/.littlefs.bin to an ESP8266 with --erase-all; esptool v4.8.1 skips the image chip check for ESP8266 (cmds.py:345), so nothing stops it today (recoverable over USB with a 1.x image). Task A, dev line. From the first release built with this change, the loose release assets contain no name any 1.x matcher accepts: flash_otgw.sh and flash_otgw.bat globs (*.ino.bin, *.littlefs.bin, OTGW-firmware-*.ino.bin, OTGW-firmware*.littlefs.bin) and flash_esp.py substrings (.ino.bin, fw.bin, firmware.bin, littlefs.bin, fs.bin, filesystem.bin). Recommended: publish the app and filesystem images only inside the -flash.zip (names unchanged, the update page of units on earlier 2.x betas needs them, update.html:241), plus merged-full.bin, the safeboot image, the .elf and SHA256SUMS. The rule applies to betas as well. Consumers to update: scripts/beta_publish.py, the /release-2x asset list and its MUST print N count, scripts/ota_flash.py, scripts/device-verify.sh, scripts/ha-ingress-rig/ota_via_ingress.py, dev flash_esp.py fallback path, docs that tell users to download loose files. Grep for ino.bin and littlefs.bin outside backlog/ and list each hit as changed or not needed.
