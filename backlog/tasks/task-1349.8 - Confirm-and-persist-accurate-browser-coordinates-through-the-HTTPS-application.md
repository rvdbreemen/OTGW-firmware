## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Existing detection immediately saves browser coordinates in two separate setting writes. The prototype must let a user verify the installation location and handle failures without silently accepting a wrong or incomplete result.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Detection is user-initiated in a trusted secure context and displays latitude, longitude, timestamp and reported accuracy before confirmation.
- [ ] #2 The UI explains that this is the browser location; cancel, poor accuracy, permission denial, timeout and unavailable location preserve the previous saved pair.
- [ ] #3 Confirmed valid coordinates are saved via HTTPS and read back after reboot within the documented four-decimal rounding tolerance; partial save failure is detected and leaves or restores a consistent pair.
- [ ] #4 Finite/range validation includes legitimate zero coordinates; meaningful unit tests cover failure and persistence paths without counting mocked geolocation as device proof.
- [ ] #5 Location changes do not alter boiler-control algorithms or enable weather/control automatically; changed UI and settings behaviour is documented.
<!-- AC:END -->
