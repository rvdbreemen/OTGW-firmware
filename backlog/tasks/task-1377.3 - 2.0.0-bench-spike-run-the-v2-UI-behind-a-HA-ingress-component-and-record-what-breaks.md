## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Research (docs/research/2026-10-25-home-assistant-ui-integration.md sections 4 and 5): hass_ingress README facts: modes ingress/iframe/auth/hassio; path /api/ingress/{name}/; X-Ingress-Path header and $http_x_ingress_path variable; rewrite rules (mode body/header, match/replace); headers option can set host and authorization (basic auth) with $username variables; require_admin default false; WebSocket proxying mentioned only in the TLS section; default Host/Origin/X-Forwarded-* behaviour undocumented; static_token bypasses HA login (never use). Test order: (1) current firmware, no rewrite; (2) rewrite rules for '/api/', '/ws', '/update', '/upload', '/ReBoot', '/ResetWireless', '/FSexplorer'; (3) headers host set to the device address and check isSameOriginRequest() restAPI.ino:216 / uploadSameOrigin() FSexplorer.ino:635. v2 WebSocket is on port 80 /ws, so it is in reach of the proxy. Comparison baseline: HA Webpage dashboard (blocked as mixed content under HTTPS).

2026-10-25 component comparison (AC#1), primary sources = GitHub API + project README/source:
- lovelylain/hass_ingress: 288 stars, release 1.4.0 on 2026-10-17, Apache-2.0, in the HACS default catalog, proxies HTTP and WebSocket under /api/ingress/<name>/ behind the HA login, require_admin option. Source read: ingress.py passes the browser Host through.
- HA built-in Webpage dashboard (core): an iframe, no proxy; an http:// device inside an https:// HA page is blocked as mixed content, and it gives no remote access. Only fits HA over plain HTTP on the LAN.
- Pulpyyyy/multiappproxy (HA add-on): 2 stars, first pushed 2026-10, needs HA OS/Supervisor (add-ons), so not for Container installs.
- A generic reverse proxy (nginx/Caddy) in front of the gateway: works, but outside HA login unless the user adds auth.
Choice: hass_ingress (maintained, licence fits, works on every HA install type, carries WebSocket). Same choice as 1.x TASK-1378.2.
Spike plan on dev: rig from otgw-1.x.x scripts/ha-ingress-rig, v2 probe added (v2 ids, /ws live log, 503 counters per scenario), nginx location with WebSocket upgrade, run against alpha.505 on the bench before any change.
