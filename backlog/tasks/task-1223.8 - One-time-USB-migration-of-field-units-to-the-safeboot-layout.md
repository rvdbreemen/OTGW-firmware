## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Existing 4MB units must be USB-flashed once (partition table + LittleFS offset change). Provide a migration mode in flash_otgw.bat that backs up settings (/api/v2/settings or LittleFS read-back), flashes the full new layout, keeps NVS (WiFi creds) where possible, and restores settings. Document the procedure for users.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-10-15 implemented, not yet run on the bench:
- build.py write_migration_slices() cuts merged-full around NVS into *-migrate-0x0.bin (@0x0) and *-migrate-rest.bin (@0xE000), and the dist zip includes both.
- flash_otgw.bat and flash_otgw.sh --migrate --host <ip> [--password] [--no-backup]: download settings.ini and dallas_labels.ini, write both slices without erasing (NVS and WiFi kept), wait for the unit, upload the files, reboot, then fc/cmp the downloaded settings.ini against the backup.
- flash_otgw.bat --update reads the unit's partition table (0x8000) and refuses when its layout differs from TOOL_LAYOUT, pointing to --migrate.
- Fixed pre-existing 'exit /b %ERRORLEVEL%' inside blocks, which returned a stale code.
Host test for the slicing in tests/test_build_safeboot.py.
