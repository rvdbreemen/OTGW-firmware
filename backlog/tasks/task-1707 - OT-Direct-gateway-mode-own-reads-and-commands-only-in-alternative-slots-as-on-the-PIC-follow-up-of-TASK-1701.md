## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-1701 stopped the gateway's own MsgID 0 while a thermostat is connected (hotfix, Robert 2026-11-07). The rest of the master scheduler still runs between the thermostat's frames (tjfs log: 634 own frames against 369 thermostat frames in 6 min). The PIC sends exactly one boiler frame per thermostat frame and uses its own reads and commands only in slots where the thermostat asks an ID the boiler does not support, answering the thermostat itself (gateway.asm:2384-2414 CreateRequest/SendAltRequest, 3390-3442 Alternative/SendPriorityMsg); frames of its own only without a thermostat (gateway.asm:1770-1816 StandAloneMsg). Make OT-Direct gateway mode follow that model. Consequence to weigh: values the thermostat never reads arrive slower, as on the PIC.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implementation (uncommitted in worktree wt-1707, branch lane-1707 from lane-1701; no bump, no build, no commit per the lead's job rules). OTDirect.ino: (1) otdOwnFramesAllowed() (was otdOwnStatusRequestAllowed, same markers) and scheduleMasterRequest() returns before the queue drain in gateway mode with state.otd.bThermostatConnected, so nothing goes out between thermostat frames; the TASK-1701 MsgID 0 skip is folded into it. (2) New block otdAltSlot after scheduleMasterRequest(): otdIsAltSlot() = UI= table or getUnknownCount()>=3 (3 consecutive Unknown-DataID, the PIC unknownmap rule gateway.asm:2437-2449) and no SR= entry; otdAltScheduleIndex() picks the eligible schedule entry with the largest age/interval (MsgID 0, disabled entries and writes without a value excluded); otdAltSlotTaken() takes the queue tail first, then that entry, answers the thermostat Unknown-DataID with its own Data-ID and data bytes (CreateMessage gateway.asm:3464-3471) and sends the gateway request with OT_DIRECT_ORIGIN_GATEWAY; dequeue / lastSentMs only after a successful send. otdNoteThermostatRead() restarts the schedule timer of a value the thermostat reads itself, so slots go to values it does not read. (3) loopOTDirect() gateway branch tries otdAltSlotTaken() before the UI table; no candidate or master not ready: the frame goes the old way (UI local answer, SR answer, or forward). Standalone code path untouched.

PIC model checked in other-projects/otgw-6.6/gateway.asm: HandleRequest/CreateRequest 2381-2402 (one boiler frame per thermostat frame; UnknownMask decides the alternative), SendAltRequest 2404-2414, SendAltResponse 2464-2473 (W=0x70 Unknown-DataID unless OverrideUsed), Alternative/AdminMessages/SendPriorityMsg/AltLoop 3390-3461 (init admin reads, priority msg, counter resets, then the EEPROM alternative list, default 116-123 at 5479), RestoreRequest/CreateMessage 3462-3471 (no alternative: the thermostat's own request goes to the boiler), UnknownMask 3491-3511 (IDs 128-255 never blacklisted), StandAloneMsg 1796-1816 (own frames only with NoThermostat), WordResponse 3624-3640 (SR= applied to boiler replies and to slot replies). OT spec v4.2 section 4.3.2 (docs/opentherm specification/OpenTherm-Protocol-Specification-v4.2.md:1118-1140): a gateway is transparent, may send another message to the next slave when the master's message is meant for the gateway, and answers after the slave's reply.

Deliberate differences from the PIC, for Robert to weigh: (a) timing: the thermostat gets the slot's Unknown-DataID at once (as the UI table answers today), the PIC answers after the boiler replied to the alternative (spec 4.3.2 wording); the log reads T,A then R,B instead of T,R,B,A. (b) SR= frames are still answered locally with no boiler frame; the PIC forwards them and replaces the answer (WordResponse). So a thermostat ID with an SR entry gets 0 boiler frames, not 1. (c) The candidate pool is the full schedule table (age/interval priority), the PIC rotates a short list (default 116-123). (d) The UI-table path without a candidate keeps its old reply with data 0x0000; the slot reply carries the thermostat's data bytes as the PIC does.

Consequence (MQTT values that arrive slower; measured in tests/test_otd_gateway_alt_slots.py A30, synthetic stream, 30 min, 3 unsupported IDs once per 20 s each = 261 slots): values the thermostat reads itself (in this stream 0,1,3,16,17,24,25,28) are unchanged, they come from the relayed frames. 10 s reads the thermostat does not ask (18 CH pressure, 19 DHW flow, 26 DHW temp, 29-32, 35 fan speed, 36 flame current, 38 humidity): from every 10 s to about every 2 min (15 reads in 30 min; OLD 35 in 6 min). 60 s reads (5 fault flags, 15, 20-22, 33 exhaust, 34, 37, 39, 48-63 bounds and remote params, 70-91 ventilation, 93-115, 116-123 burner/pump counters and hours, 125, 127): from every 60 s to once or twice in 30 min. Periodic writes (W entries 7, 8, 14, 24, 27, 56, 57) and queued commands go out only in slots: a queued MM= (MsgID 14) reached the boiler 11 s after it was queued (Q1). If a thermostat asks no unsupported ID at all, none of these values arrive and queued commands wait until the thermostat disconnects; the queue holds 12 MsgIDs (coalesced) and then refuses writes (TASK-1593 reports it). Writes the thermostat sends itself (MsgID 1 CS=, 16, 56/57 if it writes them) keep working through applyOverrides on its frames. SAT in OT-Direct gateway mode with a thermostat: CS on MsgID 1 rides the thermostat's frame; MM= on MsgID 14 depends on slots.
