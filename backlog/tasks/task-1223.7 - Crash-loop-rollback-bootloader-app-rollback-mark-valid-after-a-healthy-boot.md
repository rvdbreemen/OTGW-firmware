## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Bootloader fallback covers an INVALID ota_0 only. A valid-but-crashing image needs CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE and esp_ota_mark_app_valid_cancel_rollback() after a healthy boot. Investigate whether pioarduino's precompiled bootloader allows this (hybrid compile / custom bootloader), and implement if feasible. Bootloader is USB-only, so it must be right at migration.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decided 2026-10-15: investigate feasibility first. If APP_ROLLBACK works with pioarduino, it ships in the migration image (the bootloader can only be written over USB, so it must be in the one-time migration). If not, record the decision and close.

2026-10-15 feasibility, from source and binaries (docs/research/2026-10-15-crash-loop-rollback-feasibility.md): option A, the stock bootloader.
- Evidence that APP_ROLLBACK is on in the shipped bootloader: libs esp32s3/sdkconfig:423 has CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y, the disassembled bootloader_qio_80m.elf calls write_otadata on the pending->aborted path, and libapp_update.a carries the rollback-only string.
- Arduino marks the app valid in initArduino() unless verifyRollbackLater() returns true (esp32-hal-misc.c:277-290).
- Needed in the main firmware: define verifyRollbackLater(), then call esp_ota_mark_app_valid_cancel_rollback() after a short health gate, before any planned restart.
- Needed in safeboot: check esp_ota_get_last_invalid_partition() before pointing boot back at ota_0, otherwise a rolled-back image runs again.
- Handover must erase the whole otadata partition (0xE000, 0x2000).
- The migration image must write bootloader.bin at 0x0.
- Never enable anti-rollback.
Optional add-on: an app-level boot counter for crashes after mark-valid.
AC2 (crash-looping test image falls back on the bench) is done in the TASK-1223.9 run, after implementation in TASK-1223.4/.5.

Bench 2026-10-15 Classic-S3 (PIC, .88.63, COM8), alpha.424 safeboot layout; log .tmp/bench-migrate/ota.log + migrate.log:
- Crash-test image (verifyRollbackLater true, abort() in setup) uploaded through safeboot. The bootloader rolled back and safeboot reports app_rolled_back:true with the warning page.
- A reboot from safeboot does NOT rerun the bad image.
- A good image survives an RTS hard reset after the 30 s health window, which proves mark-valid ran.
- The interrupted upload plus reset lands in safeboot with app_valid:false, recovered over WiFi in 20 s.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Crash-loop rollback works with the stock pioarduino bootloader (APP_ROLLBACK already enabled): main firmware keeps a new image pending until a 30 s health gate or a planned restart marks it valid; safeboot refuses to boot a rolled-back image. Evidence: feasibility report (AC1) and the Classic-S3 bench run with a crash-test image (AC2).
