## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Field report robou1337, #english-support 2026-11-03 (msgs 1567270384078688317, 1567295206070423593, 1567295842384085123): NodoShop OTGW WiFi (Wemos D1 mini v4, ESP8266) on a Bouygues Bbox Wi-Fi 7 Ultym (France). In 802.11n the ESP associates (router shows it connected, RSSI -45..-51) but gets no usable link: no DHCP/ARP from the LAN, and after a few minutes the config AP returns. Same with OTGW-firmware 1.7.7, 1.7.8 and otgwmcu, so not a 1.7.x regression. Separate 2.4 GHz legacy SSID, simple key: no change. Other IoT devices (incl. an ESP-based thermostat) work on the same Bbox. With his own debug firmware forcing WIFI_PHY_MODE_11G it gets an IP at once (192.168.1.95) and TCP to the gateway works (11 ms). OTGW-firmware has no PHY-mode setting today. Line: otgw-1.x.x (ESP8266); check whether 2.0.0 ESP32-S3 needs the same (likely not, different radio).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-11-03 feasibility (read-only, wt-otgw-1.x.x f46a756f6): (1) API exists on the 1.x core: Arduino ESP8266 2.7.4 ESP8266WiFiGeneric.cpp:359 setPhyMode() -> SDK wifi_set_phy_mode() (user_interface.h:429); values 11B/11G/11N. (2) Precedent: Tasmota command Wifi 2/3/4 = 802.11b, b/g, b/g/n, ESP8266 only (tasmota.github.io/docs/Commands, quoted). (3) Insertion point: networkStuff.ino:383-386 (before WiFi.begin() in startWiFi) plus the loopWifi reconnect path (~:814), same spots as wifiKeepRadioAwake(). (4) Catch: the user's unit never gets an IP in 11n, so it falls back to the WiFiManager portal; the setting must be reachable without a working 11n link: either a field in the config portal, or set via another network (phone hotspot, as robou1337 already did) / settings.ini. (5) Risk (secondhand, Arduino core docs via search): an 11g client can make some routers drop to b/g for all clients; reason to keep it opt-in, default unchanged. (6) Not checked: ESPHome equivalent; whether wifi_set_phy_mode persists in SDK flash. (7) 2.0.0 ESP32-S3: separate radio stack, not assumed affected.

2026-11-03 Robert's choice: opt-in setting 'WiFi mode: auto (11n, today's behaviour) / 11g' in settings AND as a field in the WiFiManager config portal, so a user whose router fails in 11n can set it during WiFi setup without a working link. No automatic fallback.

2026-11-04: implemented on the 1.x line as 1.x TASK-1597, shipped in v1.7.9-beta.2 (622bbbe6c). Research (AC1): Tasmota Wifi 2/3/4 (support_command.ino:2993-3029, no auto fallback, WifiCheckIp support_wifi.ino:1188-1284), ESPHome phy_mode AUTO/11B/11G/11N (PR #16055, no auto fallback); 11g kept opt-in. AC3: host tests + evaluate green; bench .68 unreachable, Robert waived the bench test. AC4 field confirmation: robou1337 2026-11-04 00:10 UTC, #english-support msg 1567330104563081218: 'can confirm it works', screenshot shows 1.7.9-beta.2+622bbbe on Bbox-806ABA80, IP 192.168.1.95, web UI reachable.
