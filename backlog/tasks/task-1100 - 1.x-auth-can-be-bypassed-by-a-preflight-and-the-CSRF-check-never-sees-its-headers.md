## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Two related defects on the 1.x line, both absent or already repaired on 2.0.0. checkHttpAuth() short-circuits on OPTIONS, so a CORS preflight reaches every HTTP_ANY FSexplorer route unauthenticated. Separately, collectHeaders() registers only If-None-Match, so ESP8266WebServer discards Origin and Referer and the same-origin CSRF check can never fail, which makes a cross-origin form post to a state-changing route succeed against a browser that holds cached Basic credentials. Found by the FSexplorer audit of 2026-09-01, findings 3 and 4 of 18.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 An OPTIONS request cannot reach a protected route without credentials
- [x] #2 collectHeaders() registers the headers the CSRF check reads, and the check rejects a cross-origin post
- [x] #3 Legitimate same-origin use of the web UI is unaffected, verified on hardware
<!-- AC:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Removed the OPTIONS short-circuit in checkHttpAuth() and added Origin and Referer to collectHeaders() so the same-origin check can see them. Verified on hardware with an admin password set: an unauthenticated OPTIONS to /api/listfiles?delete=... returns 401 (was 200); an authenticated POST carrying a foreign Origin returns 403; a same-origin request reaches the handler normally. Legitimate v2 preflights are still answered upstream in processAPI(). Field note carried in the commit: origin enforcement is now live on every route that calls checkHttpAuth(), which a reverse proxy that rewrites Host may notice.
<!-- SECTION:FINAL_SUMMARY:END -->
