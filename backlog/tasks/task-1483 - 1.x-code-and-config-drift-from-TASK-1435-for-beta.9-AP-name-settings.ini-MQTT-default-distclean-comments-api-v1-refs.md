## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The docs-only part of the v1.7.7 drift audit (dev TASK-1435) is on otgw-1.x.x as 090da19ef. This task carries the items that need a bump or a maintainer decision, decided by Robert on 2026-10-29.

Items:
- (5) data/index.js:7268-7270 / :7301: the Reset WiFi confirm names the AP 'OTGW-XXXXXX'; the real AP name is <hostname>-<MAC>.
- (7) data/settings.ini ships MQTTenable false while the code default is true (OTGW-firmware.h:437). Decision: set settings.ini to true (one truth, equal to the code; existing units keep their own settings.ini on a filesystem OTA).
- (8) MQTTharebootdetection has no effect: it is deprecated by ADR-088, removed from the UI and kept for compatibility (restAPI.ino:1648). Docs-only: say so where the setting is documented.
- (14) MQTTstuff.ino:667-668 comments: SC format is H:MM/D, not day/HH:MM; the resetgateway payload must be 1. Also MQTTstuff.ino:46 (NodeId is the MAC, not the chip id), MQTTstuff.ino:990-996 ('OT retained topics', but OT values are not retained), restAPI.ino:1786 (an /api/v1 endpoint that no longer exists).
- (15) build.py --distclean promises to also remove the cores/libraries cache but does the same as --clean. Decision: make it really clear the cache (scope it to this project's PlatformIO/arduino-cli cache, never a shared core dir without saying so), and fix the --no-archive help path.
- (18) .gitmodules points at the PRIVATE repo OTGW-other-projects, so git clone --recurse-submodules fails for users. Decision: keep the submodule; add a README warning with the clone recipe that skips it.
- Extra drift from the audit: Makefile builds a 1 MB fs image; docs/api/openapi-dallas-sensors.yaml:43 and :106 still document /api/v1.
- Open, not decided: MQTT.md:33-35 and MQTT_STALE_TOPICS_CLEANUP step 3 say discovery resets on every connect; the code does that only in startMQTT() and after more than 5 min offline (MQTTstuff.ino:1005-1012). Verify against ADR-062 auto-verify, then fix the docs or ask the maintainer.
