## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-up of TASK-1679 (Robert 2026-11-07). The deepest two-tab dips (8-12 KB free on .61, beta.123) have 2 file streams in flight and an empty MQTT outbox, so they are the web path: per stream about 3.1 KB lwIP TX pbufs, 1.45 KB LittleFS chain, ~2 KB request/response objects, plus the 2.9 KB _send_buffer per _ack. Serve /favicon.ico (3627 B) from PROGMEM with a long Cache-Control (no LittleFS open, no file-gate slot), and admit at most one large body stream (e.g. > 16 KB) at a time while small files may run beside it. The earlier 40 KB free-heap threshold (beta.120, reverted) caused 12 s timeouts: use the file size at admission, not a heap threshold. Touches ADR-165 (cap 2) and ADR-194 (static assets from flash).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Two parts, one Proposed ADR (amends ADR-165 file-gate semantics; ADR-194 covers the flash favicon).
A. At most one LARGE body stream at a time, small files beside it (cap stays 2 per ADR-165). The size is not known at admission (the file opens after admission; exists() allocates fs state), so the caller classifies: webSendFile(path, mime, gzip, bool large=false). Large = the gzipped page route (FSexplorer.ino:119, v2.html.gz 170 KB / FSexplorer.html.gz) and the generic file route (FSexplorer.ino:583) when the file is > 16 KB (it already calls LittleFS.exists(); a stat there costs the same). webFileGateTryAdmit(bool large): refuse when large && webLargeInFlight >= 1 (queue it: FIFO, 10 s deadline unchanged); counter released with the slot. The queue stays strict FIFO (head-of-line): a small file behind a waiting large one waits too -- accept for KISS or let small skip? decide with advisor. No heap thresholds (beta.120 40 KB threshold caused 12 s timeouts).
B. /favicon.ico from PROGMEM: build step writes the gzip-free bytes of data/favicon.ico into a generated header (like updateServerHtml.h), served by its own route with Cache-Control: public, max-age=604800 and an ETag; no LittleFS open, no file-gate slot. data/favicon.ico stays on LittleFS (FSexplorer protected list), route registered before the static/notFound handler.
Verification: AC2 host fixture tests/fixtures/web_file_scheduling.cpp (needs host g++: use the MSVC shim or the existing harness) -- two large requests: second waits until the first ends; large + small run together; red on old code. AC3: test that the generated bytes equal data/favicon.ico and the route serves them (curl on bench: sha256 equal, no fs open counter change). AC1: two-tab A/B on .61, 5 runs, vs beta.123 and the beta.133 baseline (17.0-32.4 KB).
