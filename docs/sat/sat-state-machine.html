SAT state machines

How the 2.x firmware's SAT port runs today: firmware dev acd5e6f7c (2.0.0-beta.99), 2026-11-05, TASK-1661.

This page shows what the firmware does today, not what SAT should do. The source for SAT behaviour is Sergeant D's recorded decisions and the pinned thermo-nova code. Every fact here has a file:line citation in sat-state-machine.md, along with the full transition tables. A second reader checked the citations. Control: about 52 claim groups confirmed, 12 imprecise and 1 wrong, all fixed. Cycles and boiler: 107 rows confirmed, 9 imprecise and 2 wrong, all fixed.

How the machines fit together

Only the class of a finished burn feeds back into control: OVERSHOOT moves continuous to PWM, UNDERHEAT_PWM moves PWM to continuous. Boiler status, flame status, cycle phase and the curve recommendations are reporting only. Cycle kind acts only indirectly: kind UNKNOWN makes the class UNCERTAIN, so no switch happens. The raw flame edge also reaches the PWM start-up: it times the suppression hold and clears suppression when the flame goes out.

M1 SAT activity and MQTT-loss fallback

Decides whether SAT controls the boiler on this pass. The MQTT-loss fallback is a second source of "enabled", not a separate mode.

stateDiagram-v2
    [*] --> Inactive : initSAT()
    Inactive --> Active : enabled, gates pass, control tick due
    Active --> Inactive : not enabled or flashing, satDisable()
    Inactive --> FallbackActive : opt-in, SAT off, MQTT lost over 300 s
    FallbackActive --> Active : gates pass, control tick due
    FallbackActive --> Inactive : MQTT back, opt-in off, user enabled, or suppressed
    Active --> SafetyTripped : no command interface 5 ticks
    SafetyTripped --> Inactive : satClearSafetyTrip() on enable
    Active --> OtLinkLost : no boiler B frame 30 s, hand-back once
    Inactive --> OtLinkLost : enabled, no boiler reply 30 s after first pass
    OtLinkLost --> Inactive : new boiler B frame, flag and cache cleared
    Active --> OutsideTempMissing : no fresh outside temp, hand-back once
    Inactive --> OutsideTempMissing : boot gates, no fresh outside temp
    OutsideTempMissing --> Inactive : outside temp fresh, flag and cache cleared
  • Inactive / Active: bActive, true only after a control tick ran
  • FallbackActive: MQTT lost for more than 300 s with the opt-in set; never writes the enabled setting
  • SafetyTripped: no command interface for 5 ticks; cleared on re-enable
  • OtLinkLost / OutsideTempMissing: boiler handed back once (CS=0, CH=1, MM=T), SAT stays enabled and resumes by itself
  • MQTT loss 300 s
  • OT link loss 30 s
  • trip after 5 ticks
  • thermal safe after 2 h, flow 45

M2 Control mode

Selects how the CS is computed. A PWM request without MsgID 3 permission (HB bit 4 clear) becomes CONTINUOUS. There is no force-PWM option.

stateDiagram-v2
    [*] --> OFF : initSAT()
    OFF --> CONTINUOUS : first tick with SAT enabled
    OFF --> CONTINUOUS : initSAT, enabled, no saved PWM or not permitted
    OFF --> PWM : initSAT, enabled, saved PWM and permitted
    CONTINUOUS --> PWM : flow >= req + margin for 60 s
    CONTINUOUS --> PWM : burn classified OVERSHOOT
    CONTINUOUS --> PWM : deferred restore, first MsgID 3 permits
    CONTINUOUS --> PWM : control_mode pwm, permitted
    PWM --> CONTINUOUS : req >= effective max
    PWM --> CONTINUOUS : low-load permission withdrawn
    PWM --> CONTINUOUS : underheat 180 s
    PWM --> CONTINUOUS : off_time 0 for 300 s
    PWM --> CONTINUOUS : burn classified UNDERHEAT_PWM
    PWM --> CONTINUOUS : heater off
    PWM --> CONTINUOUS : control_mode continuous or auto
    CONTINUOUS --> OFF : satDisable()
    PWM --> OFF : satDisable()
  • OFF: SAT not controlling
  • CONTINUOUS: CS = PID output with an asymmetric clamp
  • PWM: CS from the ON/OFF schedule
  • overshoot 60 s, margin 2.0
  • underheat 180 s, margin 3.0
  • saturation 300 s
  • DHW guard 300 s

M3 PWM duty and ON/OFF phase

Inside PWM mode, decides whether the flame is requested. Runs once per tick, not during a cold cutoff. Duty = (PID output - base) / (boiler temp - base), split into five ranges.

stateDiagram-v2
    [*] --> IDLE : satPwmReset()
    IDLE --> ON : first step with flow, entry pending, onTime >= minOn
    IDLE --> OFF : first step with flow that does not start ON
    IDLE --> IDLE : hour limit reached, or DHW flame held
    OFF --> ON : elapsed >= offTime, onTime >= minOn, hour limit ok
    OFF --> ON : range 5, duty >= dutyMax
    ON --> OFF : ranges 1-4, min burn passed, elapsed >= onTime
    ON --> IDLE : no flow temperature, or satPwmReset()
    OFF --> IDLE : no flow temperature, or satPwmReset()
  • IDLE: after a reset or with no flow temperature
  • ON: flame requested; OFF-phase CS is 10 and CH is 0
  • Range 5 (duty at the top): no OFF time, MM=T, none of the ON-phase wait or minimum burn logic
  • min ON 180 s gas, 600 s heat pump
  • period 900 or 1200 s gas
  • hour limit 3 or 4 starts (gas)
  • min OFF 600 s heat pump, range 5

M4 PWM ON-phase start-up

One ON phase from its start until steady modulation suppression. Two flame-on anchors are in play: the real flame edge times the suppression hold; the tick that syncs to the flame times the minimum burn and the start-up average. They differ by up to one tick.

stateDiagram-v2
    [*] --> WaitFlame : satPwmBeginOn, flame off
    [*] --> FlameSynced : satPwmBeginOn, flame on
    WaitFlame --> FlameSynced : tick sees flame, ON clock restarts
    WaitFlame --> NoFlameTimer : tick, 180 s since phase start
    NoFlameTimer --> FlameSynced : later flame seen on a tick
    NoFlameTimer --> OffPhase : elapsed >= onTime, no min burn, can be the same tick
    FlameSynced --> Suppressed : tick, fModSupDelay passed since flame edge
    FlameSynced --> OffPhase : min burn passed, elapsed >= onTime
    Suppressed --> OffPhase : min burn passed, elapsed >= onTime
  • WaitFlame: CS = return + 18 (flame-off hold), resent every 5 s
  • FlameSynced: ON clock restarts at the sync tick
  • Suppressed: CS = flow - 1.0; the 3 s refresh keeps it current
  • NoFlameTimer: no flame after 180 s; the ON timer runs from the phase start with no minimum burn
  • ignition wait 180 s
  • suppression delay 20 s
  • refresh 3 s
  • start-up average 180 s
  • min burn 180 / 600 s

M5 Cold cutoff, CH rule and command cadence

stateDiagram-v2
    [*] --> Heating : _sat_coldCut false
    Heating --> ColdCut : requested <= cold setpoint
    ColdCut --> Heating : requested > cold setpoint + 0.5
  • Cold setpoint: 28.2 radiators, 21.0 underfloor, release at +0.5
  • CH: 0 when requested is at or below the threshold, or in a PWM OFF phase; else 1
  • CS: sent every tick and resent every 5 s
  • MM, CH: on change, plus a repair after about 60 s
  • PIC boards: a 30 s CS keepalive, which only acts while the 5 s resend is paused

M8 Cycle kind

Labels a finished burn from 1 Hz status samples. UNKNOWN makes the class UNCERTAIN; otherwise reporting only.

stateDiagram-v2
    [*] --> evaluate : flame-off, burn kept
    evaluate --> UNKNOWN : n == 0
    evaluate --> DHW : dhw over 0.8 n and ch under 0.2 n
    evaluate --> CH : ch over 0.8 n and dhw under 0.2 n
    evaluate --> MIXED : dhw over 0.1 n and ch over 0.1 n
    evaluate --> UNKNOWN : otherwise
  • CH / DHW: more than 80 % of samples one way, under 20 % the other
  • MIXED: both above 10 %
  • UNKNOWN: no samples or no rule matched

M9 Flame status

A burner health label, recomputed from scratch on evaluated ticks (at most every 10 s). Reporting only.

  • SHORT_CYCLING: last class SHORT; STUCK_ON: flame with setpoint under 5

  • PWM short below 5 % duty

M10 Curve recommendations

Two pieces of advice from the room error, never from cycles. Both are sampled only with a valid room temperature. The daily median version needs 3 days beyond 0.5 C.

Start-up timelines

One PWM ON phase (duty ranges 1-4, flame off at the start)

  1. t0 tick: ON starts, waiting for flame, start counted in the hour limit.
  2. t0 tick: CS = return + 18 (flame-off hold), CH = 1.
  3. Every 5 s: the hold CS is resent. The PIC keepalive does not fire.
  4. tF: flame edge. Boilers without a return temperature get a 20 s start-up flood.
  5. tF to tF + 20 s: only the 5 s resend of the hold.
  6. Whichever comes first: the 3 s refresh after tF + 20 s sends flow - 1.0 without setting the suppression flag; or the first tick with flame syncs, restarts the ON clock and, once 20 s have passed, sets the suppression flag.
  7. 180 s after the sync tick: the start-up average of the boiler temperature stops.
  8. Minimum burn: no ON to OFF before 180 s (600 s heat pump) after the sync tick.
  9. ON to OFF tick: CS = 10, CH = 0, suppression flag cleared.
  10. Flame-off edge: suppression flag cleared again.

With no flame after 180 s, the ON timer runs from t0 and the phase can end on that same tick.

Boot with SAT enabled

  1. initSAT: mode restored, no CS/MM/CH; the boot PM chain (PM=3, 15, 48) starts.
  2. Each pass: fallback, enable, trip, OT link and restart gates, in that order.
  3. OT link: no boiler reply 30 s after the first pass means hand-back, even after a boot hand-back.
  4. NTP wait: at most 60 s for the PID file.
  5. Decide once: valid state sends nothing; otherwise one quiet hand-back once a command interface exists. TC= is pushed here if enabled.
  6. Boiler reply gate, then the outside temperature gate (no second hand-back).
  7. Takeover: the control tick is made due at once.
